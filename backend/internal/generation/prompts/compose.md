Create the standard product passport using the section requirements below.
Return exactly one section for each standard ID, in the supplied order, plus a shared list of diagram definitions. Write a useful short title and a coherent summary for each section. Select relevant existing claim_ids, object_ids, scenario_ids and diagram_ids; never add unsupported facts or new model objects.
All 12 sections are mandatory. Use available only when there is enough evidence for a useful account. Use insufficient_evidence for gaps and explain what is missing. Use not_applicable only when evidence supports that conclusion; absence of a file is not proof of non-applicability.
Diagrams are LLM-created semantic views of the shared model. Allowed kinds: context, components, domain, data, deployment, states. Include only meaningful nodes and relations, always both endpoints of each selected relation. Reuse diagram IDs when several sections need the same view. Do not produce coordinates, HTML, JavaScript, SVG or Mermaid code; the shared renderer and ELK handle drawing.
A scenario diagram must include every object used by that scenario's steps. Prefer a small readable graph over an exhaustive dependency map. Add no decorative graphs or empty diagrams. Do not invent a deployment graph without deployment evidence.
Developer checklists must describe source-supported actions; do not invent runnable commands, environment values, test results, SLOs, owners or customer names. Keep secrets out of all generated content.
Apply the architecture communication method. Keep component structure separate from numbered execution scenarios. Use directed, specific relation labels and relation kinds that distinguish file/data transfer from calls. Do not give every repository equal diagram space or treat a repository boundary as a runtime boundary. Keep major component responsibilities, language/runtime, callers, contracts, dependencies and status in shared object cards. Do not put source paths, code links or a separate evidence section into architecture narrative; use claim references and the evidence inspector.
