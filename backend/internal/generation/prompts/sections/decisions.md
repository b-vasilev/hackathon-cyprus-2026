# decisions
Goal: explain why the product is built this way and what tradeoffs remain.
Use: ADRs, design docs, explicit code comments and issue/decision records included in the source context.
Prepare: documented decisions, context, chosen option, alternatives, constraints and consequences. Separate documented rationale from inferred rationale. Include known technical debt or unresolved design questions only with support.
Select: decision objects and supporting claims; relate them to affected components where the model has such relations.
Visual: use a dependency or boundary view only when it clarifies a documented consequence.
Missing evidence: code can establish a technology choice, but it does not establish why that choice was made. Say when rationale or alternatives are undocumented.
